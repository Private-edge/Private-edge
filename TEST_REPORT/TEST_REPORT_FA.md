1. **اجرای مجدد کامل** هر سه مجموعه‌تست پروژه از صفر (بدون استناد به نتایج قبلی)

## ۴. تحلیل عمیق خطای ۱۱۰۱

خطای ۱۱۰۱ یعنی «exception یا rejectionای که از fetch handler فرار کند». ساختار کد **۸ لایهٔ دفاعی** پشت‌سرهم دارد:

| لایه | محافظت | تست‌شده در |
|---|---|---|
| ۱. fetch handler | کل بدنه در `try/catch` → هر خطا 404 می‌شود | هارنس §۱ |
| ۲. route (WS) | `acceptTunnelSocket` در try/catch | هارنس §4 |
| ۳. route (config) | `await` + try/catch → خطای DoH مهار می‌شود | هارنس §2 |
| ۴. رویدادهای WebSocket | message/close/error هر سه در try/catch | هارنس §6 |
| ۵. زنجیرهٔ پیام‌ها | `chain.then(push).catch(→ abort 1011)` | هارنس §6 |
| ۶. pumpRemote | `void pumpRemote(...).catch(...)` | هارنس §6 |
| ۷. بستن سوکت/writer | همه با `.catch(() => {})` | بررسی کد |
| ۸. تایمرها | همه در `finally` با clearTimeout | بررسی کد |

### سناریوهای تست ۱۱۰۱ که پاس شدند (۴۷ مورد در ۷ دسته)

1. **مسیرهای HTTP عمومی** — GET/HEAD/POST، landing، 404، مسیرهای اشتباه
2. **config با DoH خراب** — fetch که reject می‌کند → 404 نه 1101
3. **env خراب** — بدون IDUS، مقادیر نامعتبر → 404
4. **WebSocket upgrade** — بدون هدر، مسیر غلط، بدون subprotocol
5. **early data معتبر/نامعتبر** — base64 خراب، بزرگ‌تر از ۸۱۹۲، پروتکل اسمی
6. **شبیه‌سازی v2rayNG** — ERL_DAT تنظیم‌نشده/۰/۲۵۶۰ + early data بزرگ ۳۰۰۰ بایتی
7. **سشن واقعی + لبه‌ها** — UUID غلط، مقصد خصوصی، پورت ۲۵، هدر ناقص، پیام متنی، پیام >1MB، URL نامعتبر در ECH، PRX_MOD=always بدون PDR، Bearer بزرگ، MAX_TUN نامعتبر، و **«در پایان: صفر unhandled rejection»**

> در طول اجرای هارنس، پردازش Node روی رویداد `unhandledRejection` مانیتور می‌شود — **صفر مورد** ثبت شد. همین برای ۱۲ سناریوی همزمانی سنگین بازبینی عمیق قبلی (۲۰ سشن موازی، شکست باز شدن سوکت‌ها، شکست در وسط خواندن/نوشتن) نیز صفر بود.
